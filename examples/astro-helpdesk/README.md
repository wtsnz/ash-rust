# Astro + ash-rust Full-Stack Helpdesk Demo

A full-stack, end-to-end CRUD demonstration showing how to connect an **Astro 5** (Node.js/Bun) frontend to an **`ash-rust`** GraphQL backend using the automatically generated **`ash-typescript`** SDK.

---

## 🌟 Highlights

1. **Zero Schema Duplication**:
   - The Rust backend declares the domain model, attributes, relationships, actions, and validations once using Ash declarations (`ResourceDef`, `ActionDef`, `Validation`).
   - `ash-typescript` compiles these directly into TypeScript interfaces, Zod validation schemas, query builders, and client methods in `frontend/src/lib/ash.ts`.

2. **Full-Stack CRUD**:
   - **Create**: Add tickets with real-time client-side Zod validation matching backend Ash constraints (length, numericality, enum status).
   - **Read**: Server-Side Rendered (SSR) on initial load for instant zero-JS paint and SEO, with nested relationship inclusion (`author` / `Representative`).
   - **Update**: Interactive status toggles (`OPEN` ➔ `IN_PROGRESS` ➔ `RESOLVED`) via type-safe mutations.
   - **Delete**: Archive and destroy tickets via `ash.ticket.close(id)`.

3. **Hybrid Architecture (SSR + React Island)**:
   - **Astro SSR (`src/pages/index.astro`)**: Fetches data on the server with the isomorphic client SDK.
   - **React Island (`src/components/TicketManager.tsx`)**: Hydrates on the client for live reactive mutations, filters, and searches.
   - **Astro API Endpoints (`src/pages/api/tickets.ts`)**: Server-side endpoints validating JSON payloads using `OpenTicketInputSchema`.

## 🚀 Quick Start

### One-Command Launch

Run the included launch script to generate the TypeScript SDK, start the Rust GraphQL server, and boot the Astro frontend:

```bash
cd examples/astro-helpdesk
./run.sh
```

### Manual Step-by-Step

#### 1. Generate TypeScript SDK & Start Rust Backend

```bash
cd examples/astro-helpdesk

# Generate TypeScript client SDK directly into frontend
cargo run --bin astro-helpdesk-server -- --codegen-only

# Start the Axum GraphQL server (defaults to port 4000)
cargo run --bin astro-helpdesk-server
```

- **GraphQL API**: [http://127.0.0.1:4000/graphql](http://127.0.0.1:4000/graphql)
- **GraphiQL IDE**: [http://127.0.0.1:4000/graphiql](http://127.0.0.1:4000/graphiql)
- **Health Check**: [http://127.0.0.1:4000/health](http://127.0.0.1:4000/health)

#### 2. Start Astro Frontend

In a separate terminal:

```bash
cd examples/astro-helpdesk/frontend

# Install dependencies with Bun or npm
bun install  # or: npm install

# Start development server
bun run dev  # or: npm run dev
```

Open [http://localhost:4321](http://localhost:4321) in your browser.

## 💡 Code Walkthrough

### 1. Ash Rust Domain Definition (`server/src/lib.rs`)

```rust
static TICKET_ACTIONS: &[ActionDef] = &[
    ActionDef::read("read").primary(),
    ActionDef::create("open")
        .primary()
        .accept(&["title", "description", "status", "priority", "author_id"])
        .validations(TICKET_VALIDATIONS),
    ActionDef::update("change_status")
        .primary()
        .accept(&["status"]),
    ActionDef::destroy("close").primary(),
];
```

### 2. Auto-Generated TypeScript SDK (`frontend/src/lib/ash.ts`)

```typescript
// Zod validation matching Rust validations exactly
export const OpenTicketInputSchema = z.object({
  title: z.string().min(5).max(100),
  description: z.string().nullable().optional(),
  status: z.enum(["OPEN", "IN_PROGRESS", "RESOLVED", "CLOSED"]),
  priority: z.number().int().min(1).max(5),
  author_id: z.string().uuid().nullable().optional(),
});

// Fluent Query Builder
const tickets = await ash.ticket
  .query()
  .include({ author: true })
  .sort("priority", "asc")
  .all();

// Action Mutations
const newTicket = await ash.ticket.open({
  title: "Database pool exhausted",
  priority: 1,
  status: "OPEN",
});
```

### 3. Server-Side Rendering (`frontend/src/pages/index.astro`)

```astro
---
import TicketManager from '../components/TicketManager';
import { ash } from '../lib/client';

// SSR: Runs on the Node.js / Bun server
const [tickets, reps] = await Promise.all([
  ash.ticket.query().include({ author: true }).sort("priority", "asc").all(),
  ash.representative.query().all(),
]);
---
<TicketManager client:load initialTickets={tickets} initialReps={reps} />
```
